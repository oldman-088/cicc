# Threat Intelligence read-only DTO handoff — candidate, not an approved host API

Agent 4 should not bind any endpoint until Agent 1/owner approves the authenticated host path, tenant/BFF contract and gateway trace mapping. Browser writes remain restricted to `POST /api/v1/coordination/tasks`; these DTOs do not introduce browser writes. The Agent 2 router below is currently tested in an independent mounted host and disposable PostgreSQL, not Agent 1's actual host.

## Existing relationship DTOs
- Relationship create/get and list `items` use `RelationshipRecord` from `relationship_analysis.py`: `relationship_id`, `source_entity`, `target_entity`, `relationship_type`, declared `confidence`, `evidence[]`, `provenance`, `temporal_context`, `confirmed`, `conflicting_intelligence`, `created_at`, `updated_at`, and `experimental_label`. Each evidence item retains `evidence_id`, `source`, collection `timestamp`, `description`, declared `confidence`, `provenance`, and label. Treat strings as untrusted text, not HTML.
- List: `{items, total, offset, limit, has_more}`. Filter and count apply to the trusted tenant only in the controlled local DB mode. Order is insertion sequence; offset pages across separate requests are not a shared snapshot.
- Traversal: `{entity_id, entity_type, max_depth, visited_entities, items: [{depth, relationship}], total, offset, limit, has_more, experimental_label}`. Edges are breadth-first with stable sequence order within each level; caps can return 422 with no partial results.
- `X-Correlation-ID`, when provided, identifies a DB-audited operation and is not a confidence value, source timestamp or caller-selected task ID. Host must explicitly link it to its trusted gateway trace. Error statuses and post-commit 503 semantics are in `M46_HOST_ADAPTER.md`.

## Offline-only proposed analysis and readiness data
`kev_correlation.KevCorrelationResult` contains source origin/URL/blob/content digests, catalog release and collection timestamps, explicit as-of and age horizon/status, selected exact-match entity types, `matches[]`, unmatched relationship IDs and an explanation. A match retains the full relationship and KEV entry, matched source/target roles, evidence collection ages and unresolved conflict payloads. It does not establish truth, source independence, a probability or conflict resolution. `EXPERIMENTAL_DEMO_DATA_ONLY` must remain visible for fixtures; a live-source label is trusted worker provenance, not cryptographic attestation of source truth.

`cisa_kev_health.KevHealth` separately reports the latest successful collection check (`never_collected`, `within_check_window`, `check_overdue`, or `future_check_time`), explicit as-of/horizon, last collection/check and source-release timestamps. The check age is **not** threat-event freshness, source truth, host readiness or a current network probe. No HTTP route, gateway field or frontend contract is approved for these Python models. The host owns readiness/integration errors; surface actual unavailable/failed/skipped states without converting them to success or inventing a confidence score.
