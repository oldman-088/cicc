# M46 Threat Intelligence implementation and verification — 2026-11-06

## New implementation
- `host_adapter.create_host_application` is an executable ASGI binding for the controlled router. It requires host-supplied verified principal, actor-specific PostgreSQL pool, metadata-only security-audit and gateway trace-link callbacks. It sanitizes errors, emits rejection/failure security events, verifies database identity on each operation and fails closed on trace/audit failure. If trace fails after DB commit, 503 does **not** imply rollback; the same idempotency key permits safe replay. See `M46_HOST_ADAPTER.md`. Eleven tests mount this adapter in an independent synthetic FastAPI host against disposable real PostgreSQL; **this is not Agent 1's actual host**.
- KEV snapshots now retain catalog extension metadata, can be reconstructed and revision-hash-checked in a read-only DB transaction, and offer a caller-configured last-successful-check health calculation. `kev_correlation.correlate_kev` provides an offline, exact-identifier join with explicit evidence/catalog age horizons, provenance and unresolved conflicts; it neither creates confidence scores nor proves relationships. P2-03 metadata and rollback are additive proposals only. `CISA_KEV_COLLECTOR_CONTRACT.md` and `KEV_CORRELATION_CONTRACT.md` document operational and trust limitations.
- The real-host acceptance harness now requires actual gateway trace→DB-correlation verification and adds a seventh authenticated list/tenant/audit case. All seven remain skipped: no approved host identity, shared integration, isolated environment or harness is available. Agent 1's reviewed head `2ef50e77a429fed35b8cc3991301608e9537d313` still treats body tenant as unverified and invokes the legacy simulated adapter.
- The prior controlled PostgreSQL API supports create/get/list/filter/pagination and bounded traversal, DB-derived tenant/actor/correlation/audit, direct table-access denial and operation-specific grants. It is not deployed to the host. No shared migration/role was applied. DB admins, unsafe role grants or compromised mappings can subvert DB audit; trusted collectors can fabricate source provenance.
