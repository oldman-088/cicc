# Relationship observation assessment — internal, experimental

`apps.threat_intelligence.intelligence_assessment.assess_observations(records, *, start=None, end=None)` is a pure internal function. The caller must provide records already authorized and scoped to exactly one tenant; it does not access the database or enforce tenant boundaries, and is not exposed through an HTTP or gateway route. It consumes existing `RelationshipRecord` and evidence models, preserving record/evidence identifiers, source, both provenance fields, both experimental labels, declared confidence and original conflict payloads.

- Confidence: counts each relationship's declared confidence and confirmed flag; identifies confirmed records without evidence. A declaration is not verification. Evidence and distinct source strings are counted, not evaluated for independence. No confidence score, reliability rating, freshness claim or factual conclusion is calculated.
- Temporal: evidence collection timestamps must be timezone-aware; output uses UTC. Optional timezone-aware bounds select `[start,end)`; start must precede end. Sort is timestamp, relationship UUID, evidence UUID. Relationship/confirmed/conflict counts refer to all input records, while evidence/source counts and observations refer only to the window. It does not infer a relationship's validity period or an event time from collection time.
- Conflicts: only explicitly supplied `conflicting_intelligence` is returned, with original payload and record attribution; no contradictions are inferred or resolved. Input dictionaries are deep copied.
- Duplicate relationship UUIDs, invalid intervals and naive timestamps raise `ValueError`; they are not silently discarded. Empty input yields empty observations and zero counts. Future scoring, reliability, conflict resolution, persistence, tenant enforcement and host APIs require agreed semantics and independent tests.
