# Relationship observation assessment — internal, experimental

`apps.threat_intelligence.intelligence_assessment.assess_observations(records, *, start=None, end=None)` is a pure internal function. The caller must provide records already authorized and scoped to exactly one tenant; it does not access the database or enforce tenant boundaries, and is not exposed through an HTTP or gateway route. It consumes existing `RelationshipRecord` and evidence models, preserving record/evidence identifiers, source, both provenance fields, both experimental labels, declared confidence and original conflict payloads.

- Confidence: counts each relationship's declared confidence and confirmed flag; identifies confirmed records without evidence. A declaration is not verification. Evidence and distinct source strings are counted, not evaluated for independence. No confidence score, reliability rating, freshness claim or factual conclusion is calculated.
- Temporal: evidence collection timestamps must be timezone-aware; output uses UTC. Optional timezone-aware bounds select `[start,end)`; start must precede end. Sort is timestamp, relationship UUID, evidence UUID. Relationship/confirmed/conflict counts refer to all input records, while evidence/source counts and observations refer only to the window. It does not infer a relationship's validity period or an event time from collection time.
- Conflicts: only explicitly supplied `conflicting_intelligence` is returned, with original payload and record attribution; no contradictions are inferred or resolved. Input dictionaries are deep copied.
- Duplicate relationship UUIDs, invalid intervals and naive timestamps raise `ValueError`; they are not silently discarded. Empty input yields empty observations and zero counts. Future scoring, reliability, conflict resolution, persistence, tenant enforcement and host APIs require agreed semantics and independent tests.

## Explicit analyst confidence calculation (experimental)

`confidence_assessment.calculate_confidence(record, ratings, *, start=None, end=None)` operates on **one caller-authorized relationship**. Each selected evidence item must have exactly one explicit `EvidenceRating`: evidence ID, analyst-supplied strength and source-reliability weight in [0,1] (exact decimal strings, up to six decimal places), stance (`supports`, `opposes`, `unknown`), assessor and rationale reference. Nothing is derived from the source name or declared confidence. The record's declared confidence/confirmed flag, evidence source/timestamps/provenance/labels and every analyst input are returned separately. This is not an empirical probability, source verification, or a production calibration.

For all-supporting evidence without explicit conflicts, the experimental score is `sum(strength * source_reliability) / sum(source_reliability)`, rounded to six decimal places using HALF_EVEN in a fixed 40-digit decimal context. Inputs, formula, and versioned code make results reproducible. No score is produced for no selected evidence, zero total weight, an opposing or unknown-only stance, mixed supporting/opposing stances, or any explicitly supplied conflict. Mixed stances are flagged `unresolved`; source-supplied conflict payloads are preserved. `none_observed` is not proof of agreement or absence of conflict. Scores never overwrite source/record declarations or promote assertions to verified. Time bounds are optional collection-time `[start,end)`; caller ratings must match exactly the selected evidence, duplicate/unknown IDs are rejected. Limit: 1000 evidence entries per record. The result is always labeled `EXPERIMENTAL_DEMO_DATA_ONLY`, independently of preserved record/evidence labels.

No assessment result is persisted or returned by the HTTP API; the caller must authorize and scope input to a trusted tenant. Detecting contradictions across different propositions, independence/corroboration, scoring calibration, automated conflict resolution, reliability evidence and production confidence policy remain unimplemented.

## Caller-defined collection-time age

`collection_freshness(observation, as_of=..., max_age=timedelta(...))` compares an evidence collection timestamp with explicit timezone-aware `as_of` and a positive caller-supplied horizon. At the boundary, age equal to the horizon is `within_window`; greater is `outside_window`; a collection time after `as_of` is `future_collection_time`, not silently clamped. It retains the full evidence observation and provenance, returns age/horizon in seconds, and supplies no default threshold. This is **collection-age classification**, not event-time, provider health, source freshness or evidence of live intelligence. It never modifies the separate confidence calculation.
