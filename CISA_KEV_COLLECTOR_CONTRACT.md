# CISA KEV GitHub mirror collector and durable snapshots

`cisa_github_collector.fetch_catalog()` retrieves the entire catalog as a pinned GitHub blob from the fixed `cisagov/kev-data` metadata/blob endpoints, not page-by-page. It checks metadata path/type/size, rejects redirects, duplicate-key JSON, malformed and oversize content, validates CVE IDs and dates, count and duplicate entries, checks encoded/decoded size and Git blob SHA-1, and returns source URL, content SHA-256, release and UTC collection timestamps. Git SHA-1 is an integrity check, not independent verification of publisher or truth beyond HTTPS/GitHub. No confidence is inferred. Synthetic injected transports are labeled `EXPERIMENTAL_DEMO_DATA_ONLY`; parsing arbitrary bytes alone creates no live-source designation.

`cisa_kev_persistence.persist_catalog()` writes one validated complete snapshot atomically into the additive PostgreSQL `ti_kev` proposal, deduplicates immutable normalized entry revisions by CVE/content, preserves snapshot membership, source URL, blob/content hashes, source release time, collection/check time, and records added/changed/removed counts in its returned result. An unchanged blob is idempotent and updates only last-checked time; advisory transaction locking serializes concurrent runs per origin. Older release timestamps are rejected rather than silently replacing newer snapshots. Network or validation failures precede the transaction; DB failure rolls it back. Historical membership permits recovery and change inspection; storage retention and disaster recovery must be set by the host owner. A successful complete source snapshot can remove entries from its **current membership** without deleting history. Same-release but different blobs are retained as separate revisions; assess source anomalies operationally.

One-shot host scheduling interface: `python -m apps.threat_intelligence.cisa_kev_persistence` with `CICC_TI_KEV_DATABASE_URL` supplied securely by the scheduler environment. Exit 0 means committed/unchanged, 1 means generic failure, 2 missing configuration. It does not log the URL or payload. Never put credentials in command-line arguments. The host owns scheduler frequency, distributed rate limiting, alerting, secret provisioning, job identity, backup/retention, and cancellation. The collector has bounded timeouts/retries/per-call spacing; 429/selected transient errors retry, numeric Retry-After up to 5 seconds is honored, longer or HTTP-date delays fail for scheduler rescheduling. 403 fails closed. No global cross-worker rate limiter or circuit breaker exists.

`p2_02_kev_storage_proposal.sql`, `p2_03_kev_metadata_proposal.sql`, then `p2_04_kev_blob_proposal.sql` are independent schema proposals; the P2-04 blob rollback, P2-03 metadata rollback, then `p2_02_kev_storage_rollback_proposal.sql` are **destructive** and requires an owner-approved backup/recovery plan. Restricted worker grants tested locally: schema USAGE, table SELECT/INSERT (including P2-04 source_blob), UPDATE only on snapshot.checked_at, sequence USAGE; no DELETE or historical record UPDATE. The worker itself is trusted: anyone allowed to call the persistence function or write as that worker could fabricate catalog provenance, and a DB owner can alter history. Do not expose that interface to application callers or interpret its `origin` as cryptographic attestation. Public-feed storage is global, not a tenant boundary or a frontend contract; source strings remain untrusted and require output encoding. No real host scheduler, shared schema or worker role is deployed.

Tests: fixture and real PostgreSQL persistence tests live in `test_cisa_kev_persistence.py`. Real-source tests are opt-in: `CICC_TEST_PG_EMBEDDED=1 CICC_TEST_LIVE_CISA_GITHUB=1 /home/user/.venv-cicc-pg/bin/python -m pytest -q apps/threat_intelligence/tests/test_cisa_github_collector.py::test_live_official_cisa_github_mirror apps/threat_intelligence/tests/test_cisa_kev_persistence.py::test_live_collection_persistence`. Both passed on 2026-11-06, the latter against disposable PostgreSQL. This does not prove production uptime, scheduling, endpoint availability or the truth of source claims.


`cisa_kev_snapshot.load_snapshot()` loads a complete persisted snapshot in a repeatable-read, read-only transaction, preserves top-level and entry extension fields, validates counts/CVE IDs, and checks each normalized stored revision against its SHA-256 key. Missing pre-migration catalog metadata fails closed; an identical successful source fetch backfills it. This is a corruption check, not protection against a privileged actor rewriting records and hashes. P2-04 preserves the original source bytes in `ti_kev.source_blob`; reload recomputes both the source SHA-256 and Git blob SHA-1, validates the full source catalog, and checks normalized entries and top-level metadata against the original bytes. This detects accidental corruption and inconsistent normalized revisions, not a malicious privileged worker/administrator who can replace both data and digests. Original bytes are not serialized in the public model. An unchanged repeat fetch backfills a missing current blob; older snapshots without retained source bytes fail closed and require recovery of their exact historical blob. A corrupt existing blob is not silently overwritten. Retention, storage quotas and backups require host ownership. `kev_correlation.py` can use the loaded snapshot for exact, explainable, tenant-caller-scoped correlation; see `KEV_CORRELATION_CONTRACT.md`.

`cisa_kev_health.check_health(engine, origin=..., as_of=..., max_check_age=...)` is a read-only operator function. It reports never-collected, within-window, overdue, and future-check clock skew with last successful check, source release and collection timestamps. It does not claim current provider availability or that source contents are fresh/true; failed jobs still need scheduler alerts. Fixture data and live data have separate origins. No host monitoring route or scheduler is deployed.


M47 source-byte verification is tested against disposable PostgreSQL for malformed/detached inputs, digest mismatch, normalized records rehashed to conceal tampering, missing-blob backfill, and transactional rollback; the separate live mirror test fetches, persists and reloads the original source bytes. The blob is bounded at 3,000,000 bytes. The worker remains a trusted service: no source hash authenticates the publisher or protects against a privileged party rewriting all corresponding metadata.
