# CISA KEV GitHub mirror collector — independent read-only component

`apps.threat_intelligence.cisa_github_collector.fetch_catalog()` performs bounded read-only HTTPS requests to the fixed GitHub API paths for `cisagov/kev-data` branch `develop`: file metadata then its pinned Git blob. It checks path/type/size, rejects redirects and malformed/duplicate-key JSON, validates CVE IDs, timestamps, catalog count and duplicate entries, checks encoded/decoded size and Git blob SHA-1, and returns parsed records with raw additional fields retained, source URL, Git blob ID, content SHA-256 and UTC collection timestamp. Git SHA-1 is an integrity check, not independent verification of truth or publisher authentication beyond the HTTPS/GitHub connection. No source-confidence score or verified designation is fabricated. Arbitrary input parsed by `parse_catalog` carries no live-source designation. A non-default injected transport is always labeled `EXPERIMENTAL_DEMO_DATA_ONLY`.

The collector uses explicit timeouts, up to three retries for selected transient errors, and per-call spacing; it has no distributed/global rate limiter, circuit breaker, Retry-After support, scheduling, persistence, backfill, tenant boundary or host integration. 403, redirect and malformed/oversize content fail closed with sanitized errors. All source strings are untrusted data and need contextual output encoding by consumers. Other provider adapters and production ingestion workflows remain unverified. `CICC_TEST_LIVE_CISA_GITHUB=1 /home/user/.venv-cicc-pg/bin/python -m pytest -q apps/threat_intelligence/tests/test_cisa_github_collector.py::test_live_official_cisa_github_mirror` runs a real network read. The live opt-in test passed on 2026-11-06; it does not prove scheduling, persistence, operational uptime, or the truth of source claims. Default tests use clearly labeled synthetic fixtures and make no network calls.
