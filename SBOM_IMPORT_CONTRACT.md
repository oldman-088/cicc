# M50 supported SBOM JSON subsets

`apps.threat_intelligence.sbom_ingestion.import_sbom` performs bounded offline translation, not full CycloneDX/SPDX schema validation or ingestion deployment. Input limit 1,000,000 original UTF-8 bytes; duplicate JSON keys, invalid JSON, non-finite JSON constants, unsupported format/version, ambiguous licenses/purls, unsupported top-level or component structures, duplicate identifiers/edges and dangling references fail with `SBOMError`. Non-modeled allowed document metadata is reported in `ignored_fields`; exact raw bytes must be retained by the authorized caller for full evidence/replay. SHA-256 identifies bytes, not publisher authenticity.

Supported **CycloneDX 1.5 JSON subset**: document `bomFormat`, `specVersion`, `serialNumber`, `version`, `metadata`, `components`, `dependencies`; only `components` and `dependencies` are translated, with the metadata fields listed as ignored if present. Components support `type` (ignored), `bom-ref`, `name`, optional `version`, `purl`, and `licenses` containing exactly one `expression` or `license.id`. Dependency records support `ref` and `dependsOn` with known refs. Nested components, compositions, vulnerability assertions and unsupported structures are rejected, not silently interpreted.

Supported **SPDX 2.3 JSON subset**: document `spdxVersion`, `SPDXID`, `name`, `dataLicense`, `documentNamespace`, `creationInfo`, `packages`, `relationships`; document metadata other than version is reported ignored. Packages support `SPDXID`, `name`, `versionInfo`, `externalRefs` restricted to at most one purl, `licenseDeclared`, `licenseConcluded`; `NOASSERTION` and `NONE` remain unknown in the quality model and their exact original strings are preserved separately in `license_statements`. Relationships only support explicit `DEPENDS_ON` between known package IDs. Other relationship types, external-document references and unsupported package fields fail closed. License expressions are not SPDX-validated or adjudicated.

Results preserve document digest, source/collection provenance and caller-supplied origin, component IDs, declarations and direct edges. UUIDs for license evidence are deterministic for identical original bytes and fields. Because the importer does not fully validate or model either standard, **both inventory completeness fields are always unknown** even when the source claims completeness. No CVEs, vulnerability links, transitive dependency paths, applicability, license compatibility, confidence or safety are inferred. Tested with synthetic `EXPERIMENTAL_DEMO_DATA_ONLY` fixtures and caller-declared links only; no live SBOM source or tenant boundary is claimed.
