# Explainable KEV–relationship correlation — independent analysis

`kev_correlation.correlate_kev(records, collected, as_of=..., evidence_max_age=..., catalog_max_age=..., cve_entity_types=...)` joins only exact case-sensitive CVE identifiers for caller-selected entity types. The caller must already have authenticated and loaded records from exactly one tenant; this pure function is not an authorization boundary or host endpoint. It preserves each relationship, evidence source/provenance/time and declared confidence, KEV entry including unknown source fields, catalog source URL/blob/content hashes, release/collection timestamps and experimental/live-origin label. Evidence and catalog collection-age classifications use explicit separate analyst horizons and `as_of`; future times are flagged. Explicit conflicts are copied and remain unresolved. An absent match only means absent from the supplied catalog and permitted entity types; it is not proof of absence from other sources.

A KEV membership match does **not** prove the relationship, exploit activity in that tenant, corroboration, independence of evidence, source reliability or a confidence score. `origin` comes from a trusted collector/persistence boundary and is not independently authenticated by this function. No score or resolution is synthesized. Inputs are capped at 1,000 relationships and 5,000 evidence items; a caller must further bound response sizes. Three deterministic offline tests use `EXPERIMENTAL_DEMO_DATA_ONLY` fixtures. No Agent 4 route or shared DTO has been approved.
